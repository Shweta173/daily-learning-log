# Day 5 — Hashing
📅 2026-11-16 · Topic: Hashing · Level: Beginner

## The idea in plain words
A **hash map** (a Python `dict`) stores **key → value** pairs, and a **hash set** (a Python `set`) stores just keys.
The magic: checking "is this key here?", adding a key, or reading its value takes about **O(1)** time — no matter how many items are stored.

How? A **hash function** turns the key into a number, and that number tells Python which "bucket" to look in. So it jumps straight to the right spot instead of scanning the whole list.

Use hashing when you keep asking **"have I seen this before?"** or **"how many times have I seen this?"**

| Need | Tool | Python | Lookup cost |
|---|---|---|---|
| Have I seen x? | Hash set | `seen = set()`, `x in seen` | O(1) |
| Where / how often did I see x? | Hash map | `pos = {}`, `pos[x] = i` | O(1) |
| Same check in a plain list | List | `x in my_list` | O(n) ❌ |

## Problem: Two Sum (LeetCode #1)
Given an array `nums` (**not sorted**) and a number `target`, return the **indexes** of the two numbers that add up to `target`. Exactly one answer exists, and you can't use the same item twice.

**Brute force** — try every pair `(i, j)` and check `nums[i] + nums[j] == target` → O(n²).

**Better** — walk the array once. For each number `x`, the partner we need is `target - x`. Keep a hash map of **number → index** for everything seen so far. If the partner is already in the map, we're done → O(n) time.

(On Day 3 we solved Two Sum II with two pointers, but that needed a **sorted** array. Sorting here would lose the original indexes — hashing doesn't need sorting.)

```python
def two_sum(nums, target):
    seen = {}   # number -> index where we saw it

    for i, x in enumerate(nums):
        need = target - x          # the partner that would complete the pair
        if need in seen:           # O(1) check: have we met the partner already?
            return [seen[need], i]
        seen[x] = i                # remember x for future numbers

    return []                      # no pair found (won't happen per the problem)


print(two_sum([2, 7, 11, 15], 9))  # [0, 1]  (2 + 7)
print(two_sum([3, 2, 4], 6))       # [1, 2]  (2 + 4)
print(two_sum([3, 3], 6))          # [0, 1]  (3 + 3)
```

Why add `x` **after** the check? So a number can't pair with itself — in `[3, 2, 4]` with target 6, the first `3` must not match itself.

## Dry run: nums = [3, 2, 4], target = 6
| i | x | need = 6 − x | need in seen? | seen after this step |
|---|---|---|---|---|
| 0 | 3 | 3 | no (seen is empty) | {3: 0} |
| 1 | 2 | 4 | no | {3: 0, 2: 1} |
| 2 | 4 | 2 | yes → index 1 | return [1, 2] |

Answer: **[1, 2]**

## Complexity
- Time: O(n) — one pass, and each dict lookup/insert is O(1) on average
- Space: O(n) — the dict can hold up to n numbers

## Key takeaway
Hashing trades **memory for speed**: spend O(n) space to turn an O(n) "search the list" into an O(1) "ask the dict". Whenever a brute force has an inner loop that just **looks for** something, try replacing that loop with a set or dict.
