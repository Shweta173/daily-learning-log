## The idea in plain words
A **string** is just a sequence of characters, so most array tricks (indexes, loops, two pointers) work on strings too.

Two things are special about strings in Python:
1. **Strings are immutable** — you can't change a character in place. `s[0] = "x"` is an error. Every "change" makes a **new** string.
2. Because of that, doing `result += ch` inside a loop can be slow (it copies the string again and again). Instead, collect pieces in a **list** and do `"".join(pieces)` once at the end.

Handy built-in helpers:

| Need | Python | Example |
|---|---|---|
| Is it a letter or digit? | `ch.isalnum()` | `"a".isalnum()` → True, `","` → False |
| Lowercase | `ch.lower()` | `"A".lower()` → `"a"` |
| Reverse | `s[::-1]` | `"abc"[::-1]` → `"cba"` (makes a copy, O(n)) |
| Build a string fast | `"".join(list)` | `"".join(["a", "b"])` → `"ab"` |
| Character code | `ord(ch)` | `ord("a")` → 97 |

## Problem: Valid Palindrome (LeetCode #125)
A phrase is a **palindrome** if, after making everything lowercase and removing everything that is not a letter or digit, it reads the same forwards and backwards.
Given a string `s`, return `True` if it is a palindrome, else `False`.

Example: `"A man, a plan, a canal: Panama"` → cleaned `"amanaplanacanalpanama"` → **True**.

**Brute force** — build a cleaned copy of the string, then compare it with its reverse: `cleaned == cleaned[::-1]`. Easy to write, O(n) time, but it uses **O(n) extra space** for the copy and its reverse.

**Better** — use **two pointers** (Day 3!) directly on the original string. `left` starts at the beginning, `right` at the end. Skip anything that isn't a letter/digit, then compare the two characters (lowercased). If they ever differ → not a palindrome. Same O(n) time, but **O(1) extra space**.

```python
def is_palindrome_brute(s):
    # Build a new cleaned string: only letters/digits, all lowercase
    cleaned = "".join(ch.lower() for ch in s if ch.isalnum())
    return cleaned == cleaned[::-1]     # compare with its reverse


def is_palindrome(s):
    left, right = 0, len(s) - 1

    while left < right:
        # Move left forward until it points at a letter/digit
        while left < right and not s[left].isalnum():
            left += 1
        # Move right backward until it points at a letter/digit
        while left < right and not s[right].isalnum():
            right -= 1

        # Compare the two characters, ignoring case
        if s[left].lower() != s[right].lower():
            return False

        left += 1
        right -= 1

    return True     # every pair matched


print(is_palindrome("A man, a plan, a canal: Panama"))  # True
print(is_palindrome("race a car"))                      # False
print(is_palindrome(" "))                               # True  (empty after cleaning)
print(is_palindrome_brute("Was it a car?"))             # False
print(is_palindrome("No 'x' in Nixon"))                 # True
```

## Dry run: s = "ab,A"
Indexes: 0 = `a`, 1 = `b`, 2 = `,`, 3 = `A`

| Step | left | right | What happens | Compare | Result |
|---|---|---|---|---|---|
| 1 | 0 (`a`) | 3 (`A`) | both are letters | `a` vs `a` | match → move in |
| 2 | 1 (`b`) | 2 (`,`) | `,` is skipped → right = 1 (same spot as left) | `b` vs `b` | match → left = 2, right = 0, loop stops |

Answer: **True** — `"ab,A"` cleans to `"aba"`, which is a palindrome.

## Complexity
- Brute force: Time O(n), Space O(n) (cleaned copy + reversed copy)
- Two pointers: Time O(n) — each pointer moves across the string at most once; Space O(1)

## Key takeaway
Treat a string like an array of characters — two pointers, sliding windows and hashing all work on it. Remember strings are **immutable**: avoid building them with `+=` in a loop, and if you can answer the question by just **reading** the string with pointers, you don't need to build a new one at all.
