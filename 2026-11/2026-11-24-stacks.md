# Day 11 — Stacks
📅 2026-11-24 · Topic: Stacks · Level: Beginner

## The idea in plain words
A **stack** is a pile where you can only touch the **top**. Think of a stack of plates: you put a new plate on top, and you take a plate off the top. The last plate you put down is the first one you pick up. This rule is called **LIFO** — *Last In, First Out*.

In Python, a normal list works as a stack:
- `stack.append(x)` — **push** `x` on top
- `stack.pop()` — **pop** (remove and return) the top item
- `stack[-1]` — **peek** at the top without removing it
- `not stack` — check if the stack is empty

| Operation | What it does | Python | Time |
|---|---|---|---|
| push | put an item on top | `stack.append(x)` | O(1) |
| pop | remove the top item | `stack.pop()` | O(1) |
| peek | look at the top item | `stack[-1]` | O(1) |
| is empty | any items left? | `not stack` | O(1) |

Stacks are perfect when the **most recent thing you saw is the first thing you need to deal with** — like matching brackets, the "undo" button, or the browser back button.

## Problem: Valid Parentheses (LeetCode #20)
Given a string `s` containing only `(`, `)`, `{`, `}`, `[`, `]`, decide if it is valid. A string is valid when:
1. Every opening bracket is closed by the **same type** of bracket.
2. Brackets are closed in the **correct order**.

Examples: `"()[]{}"` → `True`, `"([)]"` → `False`, `"{[]}"` → `True`

**Brute force** — **keep deleting matched pairs**: as long as the string contains `"()"`, `"[]"` or `"{}"`, remove them. If the string ends up empty, it was valid. It is easy to understand, but each pass scans the whole string and we may need up to n/2 passes, so it is **O(n²)** time.

**Better** — **use a stack**: walk through the string once.
- If you see an **opening** bracket, push it on the stack.
- If you see a **closing** bracket, the top of the stack must be the matching opening bracket. If the stack is empty or the top doesn't match, return `False`. Otherwise pop it.
- At the end, the stack must be **empty** (no opening bracket left unclosed).

The stack always holds the brackets that are "still waiting" to be closed, with the most recent one on top — exactly the one that must close next.

```python
def is_valid_brute(s):
    # Brute force: keep removing matched pairs until nothing changes
    while "()" in s or "[]" in s or "{}" in s:
        s = s.replace("()", "").replace("[]", "").replace("{}", "")
    return s == ""                  # empty means every bracket matched


def is_valid(s):
    # Better: one pass with a stack
    pairs = {")": "(", "]": "[", "}": "{"}   # closing -> its opening
    stack = []
    for ch in s:
        if ch in pairs:                       # closing bracket
            if not stack or stack[-1] != pairs[ch]:
                return False                  # nothing to match, or wrong type
            stack.pop()                       # matched: remove the opener
        else:                                 # opening bracket
            stack.append(ch)
    return not stack                          # leftover openers = invalid


print(is_valid("()[]{}"))        # True
print(is_valid("([)]"))          # False
print(is_valid("{[]}"))          # True
print(is_valid("(("))            # False
print(is_valid("]"))             # False
print(is_valid_brute("{[()]}"))  # True
print(is_valid_brute("(]"))      # False
```

## Dry run: `s = "{[]}"`

| Step | ch | Type | Action | Stack after |
|---|---|---|---|---|
| 1 | `{` | opening | push | `['{']` |
| 2 | `[` | opening | push | `['{', '[']` |
| 3 | `]` | closing | top is `[` → match, pop | `['{']` |
| 4 | `}` | closing | top is `{` → match, pop | `[]` |
| end | — | — | stack is empty → return True | `[]` |

Now `s = "([)]"`: push `(`, push `[`, then `)` arrives but the top is `[` → mismatch → **False**. The stack shows that `[` was opened last, so it must be closed first.

## Complexity
- Brute force (remove pairs): Time O(n²) — up to n/2 passes, each scanning the string; Space O(n) — new strings are created
- Stack: Time O(n) — each character pushed/popped at most once; Space O(n) — in the worst case (all openers) the stack holds every character

## Key takeaway
When the **newest unfinished thing must be finished first**, reach for a stack. Push what's waiting, pop when it's resolved, and check the stack is empty at the end. This same pattern powers expression evaluation, "undo", and tomorrow's ideas like monotonic stacks.
